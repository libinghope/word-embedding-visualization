# 下一阶段功能开发规划：跨领域连接与创新假设探索

版本：v1.0 · 日期：2026-10-26 · 状态：P0–P1 已实现；P2–P4 待实施

本文件描述开发范围和验收约定。2026-10-26 已交付 P0–P1 的确定性桥梁查询、双领域输入、结果表及点云联动；其余功能仍为规划。沿用现有 FastAPI、Vue、Pinia、Three.js 架构，逐步将词向量探索扩展为可追溯的跨领域连接探索。

## 1. 目标与边界

核心用户问题：两个不同领域之间，是否存在值得进一步研究的共同概念、技术或机制？

目标流程：输入两个领域 → 检查领域表示 → 查找桥梁概念 → 查看两侧关系及原文证据 → 保存候选假设 → 制定验证步骤。

交付分为两级：第一阶段提供可复现的向量候选；第二阶段提供可追溯的文献连接。只有第二阶段可以标为“有文献支持的连接”，且文献支持不等于假设成立。

不以自动发现重大科学原理、判断项目盈利或证明专利新颖性为验收目标。第一版不建设全自动联网采集、账号体系、公开托管和自主执行实验能力。

## 2. 当前基础与缺口

| 已有能力 | 下一步需要补齐 |
|---|---|
| fastText 中英对齐向量；当前子集为 768 英文词、232 中文词 | 领域术语覆盖与明确的检索范围 |
| 原始 300 维余弦相似度、最近邻、向量加减 | 双领域表示、桥梁候选排序与解释 |
| PCA/UMAP 三维点云 | 区分领域词、桥梁词与证据连接 |
| 最多 10 个输入词、定位、投影半径邻域、清空 | 独立的双领域输入与结果状态 |
| 校验、构建元数据、自动化测试 | 文献来源、证据强度、历史回测 |

现有投影邻域只描述当前三维布局。新功能的候选检索必须在原始高维空间计算，不能使用三维距离评分。

现有文档中“标签仅限选中/悬停/前 5 个结果”和笼统的模型许可描述已落后于实现；开发时分别更新标签规则及 Google News、fastText 的来源约定。

## 3. 用户功能

### 3.1 双领域输入

- 新增“连接探索”模式，保留现有“词语探索”。
- A、B 两组各输入 1–5 个种子词，合计最多 10 个；组内去重，跨组重复词标为共同输入并提示其降低区分度。
- 第一阶段只接受当前数据集内的完整词条，显示匹配建议、未收录词和实际使用词，不静默丢弃输入。自由问题描述在文献阶段支持。
- 支持交换 A/B、一键清空、单词移除。清空取消待处理请求并清除连接结果；切换数据集清空全部领域状态。
- 显示数据集、模型、候选词数量及语言范围；中英混合输入不能被误称为自动领域理解。

### 3.2 桥梁候选

- 默认返回 20 项，可选 10/20/50 项；排除两侧所有输入词。
- 每项显示候选词、与 A/B 的相似度、连接分数、排序依据及“仅向量关联”状态。
- 支持最低双侧相关度过滤。过滤后不足数量时返回实际数量，不补入不达标词。
- 点击候选定位，并突出显示输入词和桥梁词；连线明确表示关联，不能画成未经证实的因果箭头。
- 表格是完整结果入口；画布标签做遮挡控制，不因标签隐藏而丢失结果。
- 无结果时说明可能是词表覆盖、输入差异或阈值限制，允许调整条件。

### 3.3 原文证据（第二阶段）

- 支持导入带来源信息的 UTF-8 JSONL 文献记录，先处理标题和摘要；第一版不解析任意 PDF。
- 点击候选查看 A↔候选、候选↔B 两侧证据。每段显示原文、标题、年份、来源链接和记录 ID。
- 区分“只在语义上相近”“有原文讨论关联”“原文报告实验结果”；不从相似度自动推断后两种状态。
- 两侧证据都存在仍只能形成候选连接；A↔候选和候选↔B 不保证 A↔B 成立。
- 同时保存反对证据、适用条件和缺失信息。检索不到先例显示“当前语料未检出”，不能显示“首次发现”。

### 3.4 假设工作台（第三阶段）

保存假设卡片：问题、目标对象、桥梁概念、推测机制、支持与反对证据、关键假设、下一步验证、失败判据、状态、数据版本。

商业卡片增加：用户痛点、现有替代方案、付费意愿待验证点、成本约束、最小需求实验。科学卡片增加：可检验预测、对照条件、测量指标、可能的混杂因素。

初版使用结构化模板与人工编辑，无需外部大模型。后续可选模型辅助起草，但须引用真实证据 ID，并将推测与引用分开；缺失证据不得生成伪引文。

## 4. 算法与计算约定

### 4.1 第一版：确定性桥梁排序

令 u(w) 为现有 300 维词向量的单位向量。每组使用等权平均后归一化：

```
a = normalize(mean(u(w), w ∈ A))
b = normalize(mean(u(w), w ∈ B))
sA(c) = dot(u(c), a)
sB(c) = dot(u(c), b)
bridge(c) = min(sA(c), sB(c))
```

采用双侧较小值作为基线，避免候选仅与一侧高度相关就占据榜首。默认要求 sA、sB 均 ≥ 0，用户可提高阈值；该默认值只是操作起点，需在评价集上校准。

并列依次按双侧平均分降序、稳定候选 ID 升序排序；排序使用未四舍五入的数值。计算用 float64，结果限制在合法余弦范围。领域平均向量范数 ≤ 1e-12 时拒绝查询并提示更换输入。

新领域平均使用单位向量，现有词语类比仍使用原始向量加减；两种语义契约分别记录。分数不是概率、创新程度或商业成功率。

默认允许完整候选展示，包括通用词。后续可提供版本化停用词表及多样性重排，并同时保留基线排序，避免隐蔽筛选。两个输入领域的距离仅作为描述，不能直接计为创新奖励。

### 4.2 数据扩展

第一阶段先用已有 1,000 词完成端到端验证。第二阶段首先定义一个具体领域对及语料范围，再建立领域词表，不能把通用词表的结果质量外推到科学发现。

完整模型检索与三维展示分离：服务端候选可更大，画布只加载有限子集。扩容前解除 Dataset 中固定 1,000×300 的硬约束，升级 schema 并保留旧版读取；明确检索词表与可视化子集两个范围。

首版不直接将完整数百万词模型加载为多个 float64 副本。按选定领域先构建较小候选集，测量内存与延迟后再决定是否使用磁盘映射或近似索引。近似索引须记录参数并与精确检索对照。

### 4.3 文档向量与证据

文献阶段选择并固定支持目标语言的句子/文档编码模型，比较至少两个候选模型在人工标注检索集上的效果后确定，不在本规划中锁死型号。

文档向量与 fastText 词向量属于不同空间，禁止直接点积、相加或合并 PCA。使用概念文本、文献 ID 和明确的检索步骤连接两者。

记录模型版本、文本切分方式、归一化、来源哈希、语料截止日期与构建参数。摘要中的否定、条件与实验对象应保留，避免切分后改变原意。

## 5. 数据结构与接口草案

### 数据对象

| 对象 | 必需内容 |
|---|---|
| BridgeQuery | dataset_id、A/B 词条、k、双侧最低阈值、算法版本 |
| BridgeResult | candidate_id、词条、sA、sB、bridge、证据状态 |
| Document | doc_id、标题、摘要、语言、年份、来源 URL/标识、许可说明、内容哈希 |
| Evidence | evidence_id、doc_id、原文片段及字符位置、关联对象、支持/反对/不确定、标注方式 |
| Hypothesis | hypothesis_id、卡片字段、证据 ID、数据/算法版本、创建及修改时间 |

所有 ID 与数据版本绑定；来源缺失或年份未知如实标记。只有满足时间切分要求的记录可进入历史回测。

### 接口

- `POST /api/v1/bridges`：双领域候选检索，返回输入解析、候选范围、算法参数、分项分数和结果。
- `GET /api/v1/corpora`：第二阶段语料清单与版本。
- `POST /api/v1/evidence/search`：按领域与桥梁概念检索原文，保留检索分数与证据判断的区别。
- `POST /api/v1/hypotheses`、`GET /api/v1/hypotheses`、`PATCH /api/v1/hypotheses/{id}`：第三阶段本地假设保存与编辑。

复用现有错误结构；明确空输入、OOV、无效阈值、近零中心、数据版本失效和证据缺失。空结果属于成功响应。请求序号或取消机制防止旧结果覆盖新输入；切换投影不重算桥梁排名。

第一阶段保持无数据库；文献与假设阶段引入本地 SQLite，记录 schema 版本与迁移。文献导入通过离线 CLI 完成，不从用户输入的任意 URL 自动抓取。

## 6. 实施顺序与阶段交付

| 阶段 | 工作内容 | 可验收交付 | 进入下一阶段的条件 |
|---|---|---|---|
| P0：契约与基线 | 固定公式、接口、人工小向量样例、更新现状文档 | API/算法约定与评价样例 | 分数及异常情况可独立复算 |
| P1：词向量连接探索 | 双领域表单、后端排序、分项表、点云联动、清空与错误恢复 | 现有 1,000 词可运行版本 | 数学、交互与性能验收通过 |
| P2：领域数据及证据 | 确定领域对、导入语料、文档检索、双侧原文与反证 | 有来源的连接探索版本 | 来源可追溯、检索评价达到预先登记目标 |
| P3：假设工作台 | 结构化卡片、人工编辑、本地保存与导出 | 可复查的研究/商业假设列表 | 每条卡片有验证步骤及证据缺口 |
| P4：发现能力评估 | 时间切分、基线比较、人工盲评、结果分析 | 评估报告与继续/调整结论 | 有证据表明优于简单检索基线后再扩容 |

下一次开发建议只实施 P0–P1，避免将数据工程、生成模型和词向量算法混在一次改动中。此规划不触发下载新模型或付费 API。

## 7. 验收标准

### P1 功能与正确性

- A/B 各 1–5 词，总数最多 10；重复、未收录、空输入都有明确行为。
- 小向量手算结果与实现一致；覆盖仅靠近一侧的候选、并列、近零中心、过滤、输入排除。
- 交换 A/B 后 bridge 与排名不变，sA/sB 互换；切换 PCA/UMAP 不改变任何高维分数。
- 清空、切换数据集后，过期请求不能恢复旧结果；搜索、类比、现有十词选择继续可用。
- 桌面、移动端、无 WebGL 场景均能通过表格查看候选；结果不只依赖颜色表达。
- 当前 1,000 词、已加载数据下，以 100 次请求记录服务端 p50/p95；目标 p95 < 200 ms，记录机器及并发条件。目标尚未测量，不作为既成性能声明。
- 前端类型检查、构建、相关单元/API 测试和浏览器端到端测试通过。

### P2–P4 内容质量

- 每条展示的引文可定位到导入原文；来源、时间、许可字段可检查，不能伪造缺失字段。
- 建立至少 20 个领域对的试验评价集，覆盖已知联系、无明显联系及容易产生错误关联的案例。
- 与单侧最近邻、双侧平均分和关键词检索比较；分别报告双侧相关性、通用词比例、证据覆盖、候选多样性。
- 邀请领域评审者独立判断“值得验证”，报告分歧；该指标不等于科学正确性或市场成功。
- 历史回测不仅限制文献年份，还必须检查词向量/编码模型训练数据的时间泄漏。若无法排除，只报告回顾性检索效果，不声称提前预测。
- 在评估前固定查询、阈值、数据切分及成功标准；报告失败案例，不只展示精选成功案例。

## 8. 风险与应对

| 风险 | 处理方式 |
|---|---|
| 通用词成为所有领域的桥梁 | 分项分数、停用词实验、多样性评估，保留基线 |
| 领域词不在当前词表 | 明确 OOV，先补领域数据，再讨论结果质量 |
| 多义词及跨语言偏差 | 显示语境与语言；文献阶段使用上下文检索及人工核查 |
| 图形造成因果或创新错觉 | 线条注明关系类型，不用三维距离与视觉中心度评价价值 |
| 有关联但无可行应用 | 强制卡片填写机制、约束、反证及最小验证步骤 |
| 来源受限或不可再分发 | 保留来源与许可记录，单独决定可公开的内容范围 |
| 大模型生成可信外观的错误解释 | 模型为可选项；引用校验、推测标记、人工编辑 |
| 扩容引起内存及延迟问题 | 分离候选索引与画布数据，先基准测试再选索引 |

## 9. 开发前与后续决策

P0–P1 可直接基于本规划实施，不依赖外部账号。进入 P2 前需要确定首个领域对、语料来源与语言范围、可用资源，以及是否允许外部模型服务；这些决策不阻塞第一阶段。

规划成功的标志是用户能够理解、复算并追溯候选连接，知道下一步如何验证。真正的发现价值需要随后通过领域评审、实验或市场调查证明。
